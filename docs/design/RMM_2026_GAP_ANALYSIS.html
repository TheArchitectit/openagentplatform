⇌ WireGuard + SSH Tunnel Architecture

A single encrypted mesh fabric closes both the remote-desktop and self-update gaps. WireGuard provides the mesh transport; SSH provides per-session auth and port forwarding on top — defense in depth, like Tailscale.

⚡ Architecture Decisions

Each decision recorded from the sprint review, with rationale grounded in the competitive landscape.

Critical

WireGuard mesh, not per-feature transport

Instead of building a WebSocket relay for VNC and a NATS push for updates, agents form a WireGuard mesh. One fabric serves every binary data need: VNC, RDP, file transfer, self-update. The server is coordination-only — it never sees data plane traffic. This matches Tailscale's proven architecture and eliminates N separate transport builds.

Critical

SSH on top of WireGuard, not instead of it

WireGuard encrypts the mesh transport at the kernel level. SSH adds per-session authentication, fine-grained port forwarding (-L / -R), and an audit trail of who connected to what. Defense in depth: even if WireGuard is misconfigured, SSH still gates access. This is how Tailscale does it — WireGuard for mesh, SSH for interactive sessions.

High

Ed25519 code signing for self-update

Agent binaries are signed with an Ed25519 private key at build time. The agent embeds the public key and verifies every update before applying, regardless of transport. The update is delivered through the WireGuard tunnel (not a NATS push). Rollout is operator-gated: staged deployment with version pinning. No silent auto-update.

Medium

Control plane stays on NATS mTLS

Heartbeats, check results, patch commands, KB state, alerts, and policy violations remain on the existing NATS mTLS subjects. The WireGuard mesh carries only the data plane: VNC, RDP, file transfer, and update delivery. This keeps the control plane fast (message-oriented) and the data plane encrypted (stream-oriented), each on the transport that suits it.

High

Session admission reuses existing auth

Before an operator can SSH into an agent, the server validates the request against the same RBAC + org-scoping used for the shell bridge today. The server issues a short-lived certificate or authorizes the WireGuard peer — the operator's identity follows them into the tunnel. No separate auth layer for the mesh.

Medium

Scheduling grammar deferred

RMM-06 (automated tasks / cron scheduling) is deferred. Cron-style is the likely choice but the build focus is on the tunnel fabric first — it's the gap that every prospect asks about. Scheduling can ship in a later sprint without blocking the tunnel.

✦ Advantages No Competitor Has

These are features that exist in OAP today and don't exist in any of the four market leaders. They're the wedge.

Differentiator

A2A / LLM Agent Orchestration

No other RMM has a built-in A2A gateway with multi-framework LLM orchestration. OAP agents can delegate to language models, chain tool calls, and return structured results — all within the RMM's auth and audit boundary. This is the "AI-native RMM" position.

Differentiator

OPA / Rego Policy Engine

Full Rego-based policy engine with 9 posture collectors, violation tracking, and site-wide evaluation. Most RMMs have hardcoded compliance checks; OAP lets you write arbitrary policy logic. This is infrastructure-as-code for compliance.

Differentiator

Hash-Chained Audit Log

Every audit event is linked to the previous one via a cryptographic hash chain. The chain is verifiable via a dedicated API endpoint. No other RMM provides tamper-evident audit — this matters for HIPAA, SOC 2, and PCI-DSS.

Differentiator

Offline Ed25519 Licensing

Feature gating with Ed25519-signed offline license keys. No call-home, no cloud dependency for license verification. This matters for air-gapped environments and MSPs managing sensitive networks.

Differentiator

Open Source Core (BSL)

The entire RMM core is open source under the Business Source License. No other production RMM is open source. This is the trust differentiator: MSPs can audit the agent binary, verify data handling, and contribute fixes.
